# 内容规范

## 1. 版权红线

| ✅ 可以 | ❌ 不可以 |
|---|---|
| 依据官方手册的**事实**，用自己的话写知识点 | 复制商业网站、App、出版社的题目或解析 |
| 原创题目、原创解析、原创记忆钩子 | 从 lifeintheuktestweb.co.uk 等网站爬取题库 |
| 引用手册的章节名和小节名作为出处 | 大段照搬手册原文 |
| 使用 MIT 等开源许可的资料**作为参考**（并注明出处） | 直接导入许可不明的 GitHub 题库 |
| 链接到 GOV.UK 官方页面 | 使用政府标志、GOV.UK 视觉风格，或暗示自己是官方 App |

> 官方手册《Life in the United Kingdom: A Guide for New Residents》（第 3 版）是 Crown copyright，由 TSO 出版销售。**事实本身不受版权保护，但表达方式受保护。** 所以我们写知识点时一律用自己的话转述。在正式上架之前，建议就手册的使用范围做一次法律确认。

## 2. 知识点（Fact）写作规范

- **一个知识点只讲一件事**，英文 1–2 句，不超过 40 个单词。
- 必须标注出处：`source.chapter`（1–5）和 `source.section`（手册小节名）。
- 用简单英语：尽量使用 B1 水平的词汇；无法避免的术语（*Parliament*、*Reformation*）加入词汇表。
- 年份、人名、数字必须和手册一致。
- **手册与现实不一致时**：知识点按手册写，并在 `examNote` 里说明。例如：
  - 手册提到女王伊丽莎白二世为在位君主；现实中现任君主是国王查尔斯三世。`examNote` 写明“考试以手册为准”。

## 3. 题目（Question）写作规范

- 每道题关联至少一个知识点（`factIds`）。
- **每个知识点至少 2 道题**，而且问法不同（正问、反问、判断、双选），避免用户背答案。
- 题型必须是真考的 4 种之一，`examEligible: true` 的题才能进入模考。小游戏题型设为 `examEligible: false`。
- 干扰项要**合理**：同一类别（都是圣徒、都是年份），不要出明显荒谬的选项。
- 题干语法与真考风格保持一致，例如：
  - *Which of the following statements is correct?*
  - *Is the statement below TRUE or FALSE?*
  - *Which TWO of the following are …?*
- 解析（`explanation`）要回答“**为什么对，为什么其他选项错**”，不超过 3 句话。

## 4. 翻译规范

- **翻译的是意思，不是字面。** 目标是让用户读懂英语原文，而不是得到一篇优美的母语文章。
- **专有名词保留英文**，第一次出现时在括号里加母语：
  - “**Magna Carta**（大宪章）”，而不是只写“大宪章”。
  - 理由：考试是英文的，用户必须认得英文名称。
- 繁体中文不是简体的逐字转换：用词按香港习惯（例如“巴士”而不是“公交车”，“的士”而不是“出租车”，“資訊”而不是“信息”）。
- 每条翻译带质量标签：`human`（人工审校）/ `machine`（机器翻译）/ `community`（社区贡献）。
- 记忆钩子（`memoryHook`）按语言**单独创作**，没有就留空，不要硬翻译。

### 用大模型辅助翻译和出题

可以用大模型生成初稿，但必须遵守下面的流程：

```
知识点（英文，人工写）
   ├─► 大模型生成题目初稿 ──► 人工校对（答案、出处、干扰项）──► 入库
   └─► 大模型翻译初稿（quality: machine）──► 母语审校 ──► quality: human
```

- 生成脚本放在 `tools/`，提示词要求模型**只能使用提供的知识点**，不允许自己添加事实。
- 每一批生成的内容都要在 PR 里人工审阅。

## 5. ID 命名

| 类型 | 格式 | 示例 |
|---|---|---|
| 线路 | `line-<slug>` | `line-history` |
| 车站 | `st-<slug>` | `st-middle-ages` |
| 知识点 | `f-<车站 slug>-<三位序号>` | `f-middle-ages-001` |
| 题目 | `q-<车站 slug>-<三位序号>` | `q-middle-ages-001` |
| 词汇 | `t-<slug>` | `t-magna-carta` |

ID 一旦发布就**不能修改**，因为用户的学习记录靠 ID 关联。要删除内容时，把它标记为 `retired: true`，不要直接删掉。

## 6. 提交前检查

```bash
python3 tools/validate.py       # 结构、引用、答案、翻译覆盖率
python3 tools/build_content.py  # 生成 App 使用的内容包
```

CI 会在每个修改 `content/` 的 PR 上自动运行这两个命令。
