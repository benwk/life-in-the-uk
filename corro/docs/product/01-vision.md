# 01 · 产品愿景

## 一句话

**一圈节点一起盯着你的服务：多方确认故障，叫醒对的人，留下谁都改不了的记录。**

英文口号：**Uptime, corroborated.**

## 我们要解决的问题

做在线服务的团队，不管大小，都需要回答三个问题：**服务挂了没有？该叫谁？怎么告诉用户？** 现有的产品各有短板：

| 痛点 | 现状 | 用户的真实感受 |
|---|---|---|
| **误报** | 一个探测点网络抖一下，就半夜打电话 | “被叫醒三次，三次都是假的，后来我就把告警静音了” |
| **视角单一** | 探测节点集中在几家云厂商的几个机房；云厂商自己出问题时，监控也跟着瞎了 | “AWS 挂的那天，我们的监控也没报警” |
| **太重太贵** | 大厂商把 uptime 当作可观测性套件的入口，按席位和功能层层收费 | “我只想要监控和值班，却要为一整套日志平台买单” |
| **值班工具在退场** | Atlassian 已宣布 Opsgenie 停售并将停服（具体时间点需核实），Grafana OnCall OSS 也进入维护模式 | “我们得在 Opsgenie 关掉之前找到替代品” |
| **数字不可信** | 状态页上的 99.99% 是厂商自己报的，出了 SLA 纠纷，没有中立的证据 | “客户问我们拿什么证明这个月达到了 SLA，我们只能截图” |
| **内网测不到** | 公共探测节点只能测公网服务 | “数据库和内部 API 只能另外搭一套监控” |

**没有人把“谁在看、看到了什么、能不能证明”当成核心体验来设计。**这就是我们的机会。

## 愿景

> 让每一次宕机都**被多方看见**，让每一次告警都**值得醒来**，让每一个可用率数字都**经得起验证**。

我们不做“又一个探测服务”，我们做一个**圈子**：

1. **看见（Watch）**：社区节点和我们自己的基线节点组成一张全球网络。你的服务同时被不同国家、不同网络、不同运营者的节点看着。
2. **确认（Corroborate）**：一个节点的报告只是“疑似”。多个独立节点确认之后才算故障，才会叫醒人。
3. **行动（Respond）**：按排班和升级策略，用对的渠道叫醒对的人，状态页同步更新。
4. **留证（Prove）**：每一个探测结果都签了名，写进只能追加的透明日志，再定期锚定到公链。任何人都可以独立验证。

## 产品原则

1. **叫醒人之前先确认。** 误报是值班工具最大的敌人。宁可晚 30 秒确认，也不要假警报。疑似状态要看得见，但不能打电话。
2. **凌晨三点也能用。** 值班的人可能刚被叫醒，眼睛只睁开一半。告警界面只给一个最重要的动作，字要大，信息要直接。
3. **证据，而不是声明。** 界面上每一个“宕机”和“可用率”都能追溯到是哪些节点、在什么时候、看到了什么。
4. **贡献即回报。** 运行一个节点就能挣到额度。规则公开、可审计，不发币，额度不能转让。
5. **平静是默认状态。** 一切正常时，界面应该安静。颜色只在有意义时出现，红色只留给多方确认过的真实故障。
6. **五分钟上手。** 注册后 60 秒内建好第一个监控；加入网络只要一行命令。
7. **开源节点，公开方法。** 节点代码开源，共识规则和信誉算法公开。别人没法验证的“可信”不算数。
8. **不碰客户的秘密。** 社区节点只测公开端点，永远拿不到任何凭证。需要凭证的检查只在客户自己的节点上运行。

## 成功的样子

- 用户说：**“它叫醒我的每一次，都是真的。”**
- 误报：每个团队每月因误报被电话叫醒的次数 < 0.1 次。
- 速度：从故障发生到多方确认，中位数 ≤ 60 秒（1 分钟检查间隔下）。
- 网络：≥ 30% 的免费用户运行了至少一个节点；网络覆盖 ≥ 50 个国家、≥ 300 个 ASN。
- 信任：≥ 20% 的公开状态页开启了 Verified 徽章。
- 迁移：Opsgenie 用户 30 分钟内完成排班和升级策略的迁移。

## 做什么，不做什么

| 做 | 不做（至少第一版不做） |
|---|---|
| Uptime 监控：HTTP、TCP、DNS、SSL、心跳 | 日志、指标、链路追踪、APM |
| 值班排班、升级策略、多渠道告警 | 完整的事故管理平台（复盘工作流、Jira 联动等） |
| 公开状态页 | 用户行为分析、RUM |
| 社区节点网络和额度 | 发行代币，或任何可以交易、提现的资产 |
| 透明日志、公链锚定、可验证 Receipt | 把监控数据写进区块链，或者在营销中使用“Web3”这类说法 |
| 接收外部告警（Alertmanager、Grafana 等），作为值班中枢 | 自己做指标存储和告警规则引擎 |

## 名字

**Corro** 一词有三层意思，详见 [品牌手册](../brand/brand-book.md)：

1. **corroborate**：相互印证。多个节点确认同一个事实。
2. **西班牙语、意大利语、葡萄牙语里的 *corro***：“我在运行”（I run），也就是 uptime 本身。
3. **西班牙语里的 *corro***：围成一圈的人。一圈见证人围着你的服务。
