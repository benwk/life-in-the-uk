# 03 · 体验全景

## 核心隐喻：围成一圈的见证人

西班牙语里，*corro* 是一群人围成的圈。整个产品就是这样一个**圈**：

- 你的服务站在圆心。
- 来自不同国家、不同网络、不同运营者的**节点**围成一圈看着它。
- 每次检查，圈上的几个节点各自“看一眼”，给出自己的**见证**（witness）。
- 足够多的独立见证一致，结论才成立，这就叫 **Corroborated（已确认）**。
- 每一次见证都签了名、记了账，留下一张**凭证**（Receipt）。

```
           ● 法兰克福
     ● 东京          ● 圣保罗
                              
  ● 新加坡    ( api.acme.com )    ● 纽约
                              
     ● 悉尼          ● 伦敦
           ● 约翰内斯堡

  一圈节点围着你的服务。3 个以上独立节点一致 = Corroborated
```

这个隐喻要贯穿视觉设计：圆环、圆点、连线、勾选标记。Logo、加载动画、确认动画、网络地图都从它延伸出来。详见 [设计简报](../design/design-brief.md)。

## 五个产品界面

| 界面 | 域名 | 给谁用 | 一句话 |
|---|---|---|---|
| 🖥️ **控制台 Console** | `app.corro.run` | 团队成员 | 管理监控、事故、值班、状态页、节点和额度 |
| 📱 **值班 App** | iOS / Android | 值班的人 | 接告警、确认、升级、查看事故；凌晨三点能用 |
| 📄 **状态页 Status Page** | `*.corro.page`、自定义域名 | 客户的客户 | 5 秒告诉访客“是不是他们的问题” |
| ⌨️ **节点 Node** | `corro.sh` | 节点运营者 | 一行命令加入网络；带一个本地状态界面 |
| 🌍 **网络浏览器 Explorer** | `corro.network` | 所有人 | 公开的节点地图、网络统计、透明日志、验证工具 |

另外还有营销站 `corro.run`，它的首页本身就是一个实时的产品演示：显示网络当前有多少节点在线、过去一小时确认了多少次故障。

## 核心循环

```
  添加监控 ──► 节点圈开始检查 ──► 一个节点看到异常（Suspect，疑似）
                                          │
                                          ▼
                            调度更多节点从不同位置复查
                                          │
                     ┌────── 不一致 ───────┴────── 一致 ──────┐
                     ▼                                        ▼
               回到 Up，不打扰任何人               Corroborated Down → 开启事故
                                                              │
                                            按升级策略通知值班的人 → 确认 Ack
                                                              │
                                                   状态页同步 → 恢复也要多方确认
                                                              │
                                              事故时间线 + Receipt 永久留存
```

详细的状态规则见 [04 监控与共识](04-monitoring-and-consensus.md)。

## 信息架构（控制台左侧导航）

| 顺序 | 名字 | 内容 |
|---|---|---|
| 1 | **概览 Overview** | 所有服务的当前状态、正在进行的事故、今天谁在值班、最近 24 小时的确认记录 |
| 2 | **监控 Monitors** | 监控列表、监控详情（见证地图、响应时间、可用率）、新建监控 |
| 3 | **事故 Incidents** | 进行中和已解决的事故、事故时间线、Receipt |
| 4 | **值班 On-call** | 排班表、升级策略、覆盖（override）、我的值班 |
| 5 | **状态页 Status pages** | 状态页列表、编辑器、发布事故更新、订阅者 |
| 6 | **集成 Integrations** | 通知渠道（Slack、Teams 等）、外部告警源（Alertmanager、Grafana 等）、Webhook |
| 7 | **节点 Nodes** | 我的节点、私有节点池、额度余额和流水 |
| 8 | **设置 Settings** | 团队成员、角色、SSO、账单、API 令牌、审计日志 |

右上角常驻两个东西：**值班状态**（“你正在值班，到周五 09:00”）和**额度余额**。

## 值班 App 的信息架构（底部导航）

| Tab | 名字 | 内容 |
|---|---|---|
| 1 | **告警 Alerts** | 需要我处理的告警，确认（Ack）按钮最大 |

## 首次使用（Onboarding）

目标：**60 秒内**看到第一个监控被多方确认为 Up，让用户感到“这东西真的在看”。

1. **注册**：GitHub、Google、邮箱均可。不要信用卡。
2. **输入一个网址**：一个大输入框，“你想让我们看着什么？”输入 `https://acme.com`。
3. **看着节点围上来**：屏幕中间是你的网址，周围的节点一个接一个亮起、打勾，“东京 ✓ 182ms，法兰克福 ✓ 41ms，圣保罗 ✓ 230ms……”，最后出现 **Corroborated Up**。这是产品最有辨识度的时刻，要做成一段 5–8 秒的动画。
4. **谁该被叫醒？** 填手机号或者连接 Slack；发一条测试通知，确认能收到。
5. **（可选）创建状态页**：自动生成 `acme.corro.page`，预览一下。
6. **（可选）加入网络**：“有一台闲置机器？运行一行命令，换取更多监控额度。”给出 `curl -fsSL corro.sh | sh`。
7. 进入概览页。

## 关键时刻（Moments that matter）

| 时刻 | 设计意图 |
|---|---|
| 第一次看到 Corroborated Up | 节点围成一圈依次打勾，让“多方见证”这件事被看见。 |
| 出现疑似状态 | 监控旁边出现一个安静的琥珀色半圆，“1 个节点报告异常，正在复查”。**不发通知。** |
| 第一次被真正叫醒 | 通知第一行就写清楚“5 个国家的 4 个节点确认 api.acme.com 无法访问”，让人立刻相信这是真的。 |
| 疑似被否决 | 事后可以在时间线里看到“东京节点报告超时，其他 4 个节点正常，未告警”。让用户知道 Corro 替他挡掉了一次误报。 |
| 恢复 | 同样需要多方确认；值班 App 里播放一个轻柔的“解除”音效。 |
| 节点第一次见证 | 节点运营者收到消息：“你的节点刚刚帮别人确认了一次故障。”配上地图上的连线。 |
| 月末 | 自动生成可验证的 SLA 报告，一键分享给客户。 |
| 值班交接 | 周五 09:00 给下一位值班的人发一条简短的交班摘要：本周事故、未解决的问题。 |

## 术语表

界面上使用的术语要保持一致。尽量用业内通用词，只在必要处使用品牌词。

| 术语 | 中文 | 含义 |
|---|---|---|
| Monitor | 监控 | 对一个目标的持续检查配置 |
| Check | 检查 | 一个节点对一个目标的一次探测 |
| Node | 节点 | 执行检查的程序，可以是社区节点、基线节点或私有节点 |
| Witness | 见证 | 一个节点对一次检查给出的、带签名的结果 |
| Suspect | 疑似 | 有节点报告异常，但还没有被多方确认 |
| Corroborated | 已确认 | 足够多的独立节点给出了一致的结论 |
| Incident | 事故 | 一次被确认的故障，从开始到恢复 |
| Receipt | 凭证 | 可以独立验证的证据，证明某个结论在某个时间被记录过 |
| Credits | 额度 | 运行节点挣来、用于支付检查的记账单位；不能转让 |
| Responder | 响应人 | 参与值班、可以被告警叫醒的人 |
| Escalation policy | 升级策略 | 没人确认时，告警按什么顺序通知谁 |
| Circle | 节点圈 | 某个监控当前由哪些节点在看着（品牌词，少量使用） |
