# 05 · 告警与值班

## 设计目标

**让每一次告警都值得醒来，让每一个被叫醒的人在 10 秒内知道发生了什么、该做什么。**

## 通知渠道

| 渠道 | 用途 | MVP |
|---|---|---|
| **电话** | 最高级别；可以按键确认（1 = 确认，2 = 升级给下一位） | ✅ |
| **短信** | 电话的补充；回复 `ACK` 确认 | ✅ |
| **邮件** | 低级别通知和摘要 | ✅ |
| **Slack** | 频道通知，带“确认”“解决”按钮 | ✅ |
| **Webhook** | 接到任何系统 | ✅ |
| **值班 App 推送** | 支持 iOS Critical Alerts 和 Android 全屏通知，能穿透勿扰模式 | v0.2 |
| **Microsoft Teams** | 和 Slack 一样带按钮 | v0.2 |
| **Discord、Telegram** | 社区和小团队常用 | v0.3 |

**电话和短信的成本和滥用**：电话和短信要花真钱，还可能被利用来刷短信费（SMS pumping）。免费档每月有少量额度；号码首次使用前需要验证；同一号码有频率上限。

## 每个人的通知规则

每个响应人自己决定被如何叫醒，例如：

```
告警开始时  → App 推送
1 分钟后    → 短信
3 分钟后    → 电话
```

界面上提供一个**“测试我的通知”**按钮，一键把整条规则真实走一遍。让用户在半夜真正出事之前，就确认手机的勿扰设置不会挡住告警。

## 排班（Schedules）

- **轮换类型**：按天、按周、自定义；支持“跟着太阳走”（follow-the-sun），比如伦敦和新加坡各值半天。
- **层级**：一个排班可以有多层（主值班和副值班）。
- **覆盖（Override）**：临时代班；在 App 里可以直接问团队“谁能帮我值周六？”
- **时区**：每个人看到的都是自己时区的时间，同时可以切换到排班的时区。
- **日历同步**：导出 iCal，值班表会出现在个人日历里。
- **交班摘要**：交班时自动发一条摘要，包括本班的事故、仍未解决的问题、需要注意的事。

排班编辑器是一个**时间轴视图**，横轴是时间，每一行是一层；人用不同颜色的块表示，可以拖拽调整。

## 升级策略（Escalation policies）

```
生产环境 · 升级策略

第 1 级  立即      → 当前值班（主）
第 2 级  5 分钟后  → 当前值班（副）
第 3 级  15 分钟后 → 平台负责人 Tom
         如果仍无人确认，重复 2 次
```

- 每一级可以是：某个排班的当前值班、某个人、某个团队（所有人）。
- 可以按**严重程度**设置不同的策略：Down 打电话，Regional Degraded 只发 Slack。
- 可以设置**工作时间**规则：工作时间只发 Slack，非工作时间打电话。

## 告警的生命周期

| 状态 | 含义 | 谁来改变 |
|---|---|---|
| **Triggered 已触发** | 刚刚产生，正在按升级策略通知 | 系统 |
| **Acknowledged 已确认** | 有人接手了，停止升级 | 响应人 |
| **Resolved 已解决** | 问题已恢复 | 节点多方确认恢复后自动解决，或者手动解决 |

同一个事故的多条告警要**合并**：一个服务挂了，不应该因为它有 5 个监控就响 5 次。

## 告警内容的写法

被叫醒的人只看得到前两行，所以信息顺序很重要：

```
▲ api.acme.com 宕机 · 已被 4 个国家的 4 个节点确认
HTTP 503 · 从 09:41 开始 · 生产环境 · 事故 #142
[确认]  [查看]  [升级]
```

规则：

1. 第一行：**什么东西**、**什么状态**、**有多确定**。
2. 第二行：错误类型、开始时间、环境、事故编号。
3. 不写“紧急！！！”这类词，也不用全大写。确认本身就说明了严重程度。
4. 电话语音用同样的信息，语速稍慢，先说服务名，再说状态。

## 值班 App（凌晨三点设计）

值班 App 最重要的场景是：**手机在床头响了，人刚醒，眼睛只睁开一半。**

- **锁屏通知**：第一行就能看出是什么服务、多确定，可以直接在通知上确认。
- **告警页**：屏幕上半部分是状态和一句话描述，下半部分是一个**特别大的“确认”按钮**；“升级给下一位”和“查看详情”是次要按钮。
- **深色模式优先**：夜里不刺眼。跟随系统，但告警页在夜间默认深色。
- **声音**：告警音要清晰但不惊恐；同一个告警重复时逐渐变响；解除时播放一个柔和的音效。见 [设计简报](../design/design-brief.md) 的声音一节。
- **单手操作**：所有主要按钮都在拇指够得到的下半屏。

## 从 Opsgenie 和 PagerDuty 迁移

这是 Tom 这类用户最在意的事，要做成一个向导：

1. 粘贴 Opsgenie 或 PagerDuty 的 API Key（只读权限）。
2. 预览将要导入的内容：用户、团队、排班、升级策略、集成。
3. 映射用户：按邮箱自动匹配，不匹配的手动选择。
4. 一键导入；导入后给出一份对照报告，列出“已导入”“需要手动处理”的项目。
5. **并行运行**：迁移期间两边同时接收告警，确认没问题之后再切换。
