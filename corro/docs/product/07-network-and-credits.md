# 07 · 节点网络与额度

## 节点的三种类型

| 类型 | 谁运营 | 测什么 | 作用 |
|---|---|---|---|
| **社区节点 Community** | 任何人 | 别人的**公开**目标，以及运营者自己的目标 | 网络的主体；运营者挣额度 |
| **基线节点 Baseline** | Corro 自己（主要是多云、多区域的 serverless 函数） | 公开目标 | 托底：社区节点不够时补足覆盖，保证付费用户的 SLA；也解决冷启动 |
| **私有节点 Private** | 客户自己 | 客户的**内网**目标和带凭证的检查 | 只给自己用；可以选择同时作为社区节点贡献算力 |

## 加入网络

一行命令：

```bash
curl -fsSL corro.sh | sh
```

或者：

```bash
docker run -d --name corro-node --restart unless-stopped corro/node
```

还可以从 Azure Marketplace（以后加上 AWS 和 GCP）一键部署。

安装后，终端里显示一个简洁的引导：

```
  corro node v0.1.0

  ✓ 生成节点身份密钥（ed25519）
  ✓ 已连接到 corro.run（仅出站 HTTPS，不需要开放任何端口）
  ✓ 位置：维也纳，奥地利 · AS1901

  打开这个链接，把节点绑定到你的账号：
  https://app.corro.run/nodes/claim/7KQ-M2X

  本地状态：http://localhost:7979
```

设计要求：

- **只需要出站连接**，不需要开端口，不需要公网 IP，家里的路由器后面也能跑。
- **资源占用小**：单个二进制文件，默认最多占用很少的 CPU 和带宽，可以设置上限。
- **运营者可以限制**：每天最多执行多少检查、哪些时段可以运行、是否参与社区检查。
- **本地状态页**（`localhost:7979`）：显示节点在线时长、今天完成了多少次见证、挣了多少额度、信誉分。

## 额度（Credits）

额度是网络内部的**记账单位**，不是货币。

### 怎么挣

- 节点每完成一次有效见证，就挣到额度。
- 高需求地区（节点少的国家、少见的 ASN）的见证，额度更高，以此鼓励覆盖空白地区。
- 信誉分越高，每次见证挣的额度越多。

### 怎么花

- 每次检查消耗额度。检查间隔越短、每次要求的节点越多，消耗越多。
- 例：一个 1 分钟间隔、每次 3 个节点的 HTTP 监控，每月大约消耗 3 × 60 × 24 × 30 ≈ 13 万个检查单位。具体换算比例待定，要保证“一台常开的家用机器”能换到“5–10 个 1 分钟间隔的监控”。

### 规则（写进条款，也写进界面）

1. **不能转让**：额度不能在账号之间转移，也不能买卖。
2. **不能提现**：额度永远换不成钱。
3. **可以捐赠**：唯一的例外是可以捐给经过认证的开源项目账号，这只是一种“由 Corro 代为记账”的方式。
4. **可以审计**：每一笔额度的增减都写进透明日志，见 [08 可信与验证](08-trust-and-verification.md)。
5. **会过期**：12 个月不用的额度过期，防止囤积。

> 为什么这么严格：一旦额度可以转让或者换钱，它在法律上就可能被视为代币或证券，还会招来投机和反洗钱合规问题。这正是我们要避开的。

## 信誉（Reputation）

每个节点都有一个公开的信誉分（0–100），影响它能不能参与确认、能挣多少额度：

| 因素 | 怎么计算 |
|---|---|
| **一致率** | 它的见证和多数节点的结论是否一致 |
| **金丝雀检查** | 网络会混入状态已知的目标（Corro 自己控制的端点，会按计划“宕机”）；节点必须如实报告 |
| **在线稳定性** | 节点是否经常掉线 |
| **时钟和延迟质量** | 时间戳是否准确，延迟数据是否合理 |
| **账号年龄和验证** | 新节点从较低的信誉起步，逐渐提升 |

- 信誉低于门槛的节点**不参与故障确认**，只做观察。
- 被发现故意造假的节点会被移出网络，相关账号的额度冻结。
- 同一个运营者的多个节点在共识中**只算一个独立来源**，防止女巫攻击（一个人开很多节点操纵结果）。

## 防止滥用

一个任何人都能加目标的全球探测网络，很容易被滥用成 DDoS 工具或扫描器。规则：

1. **验证目标所有权**：用社区节点监控一个域名，必须先通过 DNS TXT 记录或者在网站上放一个文件，证明你拥有它。基线节点可以对少量未验证的目标做低频检查（比如免费试用）。
2. **频率上限**：每个目标在全网范围内有请求频率上限，不管多少人在监控它。
3. **节点不能选目标**：任务由协调者随机分配，节点不能挑选自己想测的目标，也不能拒绝特定目标（只能整体关闭社区检查）。
4. **只测公开端点**：社区节点永远拿不到任何凭证、Header 或 Token。
5. **出站请求标识**：节点的请求带有统一的 User-Agent，比如 `CorroBot/1.0 (+https://corro.network/bot)`，被测网站可以识别，也可以选择拒绝。
6. **运营者保护**：节点运营者的 IP 在发起请求，所以只允许请求经过验证的目标，避免运营者被卷进滥用事件。条款里要写清楚运营者的权利和责任。

## 网络浏览器（corro.network）

一个公开的网站，让网络看得见：

- **节点地图**：按城市聚合显示（**不显示精确位置**，保护运营者隐私）。
- **网络统计**：在线节点数、覆盖国家和 ASN 数、过去 24 小时的见证数和确认的故障数。
- **节点主页**（运营者可选公开）：昵称、信誉分、贡献的见证数、覆盖的地区。
- **排行榜**（可选）：按地区和贡献排序，只显示昵称。
- **透明日志浏览器**：按 Receipt 或日志条目查询，并在线验证。
- **方法论**：公开共识规则、信誉算法和金丝雀机制的说明。
