# 09 · MVP 范围与路线图

## MVP（v0.1）：先证明“多方确认 + 值班 + 状态页”成立

**目标用户**：Maya 这类独立开发者，以及 Tom 这类准备离开 Opsgenie 的小团队。

| 模块 | MVP 包含 | 以后再做 |
|---|---|---|
| **监控** | HTTP、TCP、DNS、SSL、心跳 | Ping、域名到期、带凭证的检查、浏览器检查 |
| **节点** | 基线节点（多区域 serverless）+ 邀请制的社区节点 Beta | 开放社区节点、私有节点、Azure Marketplace |
| **共识** | 默认确认规则、疑似和否决、区域性降级、时间线 | 用户自定义规则、更细的地区策略 |
| **告警** | 电话、短信、邮件、Slack、Webhook | App 推送、Teams、Discord、Telegram |
| **值班** | 单层轮换排班、覆盖、升级策略、个人通知规则、测试通知 | 多层排班、跟着太阳走、交班摘要、iCal |
| **外部告警源** | 通用 Webhook、Alertmanager | Grafana、Datadog、CloudWatch、Azure Monitor |
| **状态页** | `*.corro.page`、自定义域名、组件、事故更新、邮件订阅 | 多语言、嵌入组件、私有状态页 |
| **可信** | 签名见证、透明日志（内部可验证）、事故 Receipt | 公开日志、公链锚定、`corro verify`、月度 SLA 报告 |
| **额度** | 节点挣额度、额度换监控、额度流水 | 信誉分公开、捐赠给开源项目 |
| **界面** | Web 控制台（桌面优先，可以在手机上用） | 原生值班 App |
| **账号** | 邮箱、GitHub、Google 登录；团队和角色 | SSO、SCIM、审计日志 |

## 路线图

```
v0.1  MVP          基线节点 + 邀请制社区节点；监控、确认、告警、值班、状态页
v0.2  值班中枢      值班 App（Critical Alerts）、Teams、Opsgenie / PagerDuty 导入、更多告警源
v0.3  开放网络      社区节点全面开放、信誉分、corro.network 网络浏览器、公开透明日志 + 锚定
v0.4  企业          私有节点（Azure Marketplace）、带凭证的检查、SSO、月度 SLA 报告、数据驻留
v1.0  正式发布      多层排班、跟着太阳走、私有状态页、嵌入组件、完整的 API 和 Terraform Provider
```

## 需要验证的关键假设

| 假设 | 怎么验证 | 指标 |
|---|---|---|
| 开发者愿意运行节点换额度 | 看免费用户里运行节点的比例 | ≥ 30% 的免费用户运行至少 1 个节点 |
| 节点愿意长期在线 | 看节点的 30 天留存 | ≥ 60% 的节点 30 天后仍在线 |
| 多方确认能显著降低误报 | 对比单节点告警和确认后的告警 | 被否决的疑似占所有疑似的比例；用户报告的误报 < 0.1 次 / 团队 / 月 |
| 多方确认不会让告警变慢太多 | 测量从首次失败到确认的时间 | 中位数 ≤ 60 秒 |
| “可验证”能打动用户 | 看 Verified 徽章的开启率和 Receipt 的点击率 | ≥ 20% 的公开状态页开启徽章 |
| Opsgenie 用户会迁移过来 | 看导入向导的使用和完成率 | 导入完成率 ≥ 70%；30 分钟内完成 |

## 商业模式（初步想法，需要市场验证）

原则：**慷慨的免费档、透明的价格、没有暗黑模式；额度永远不能变成钱。**

| 档位 | 内容 | 价格方向 |
|---|---|---|
| **免费 Free** | 10 个监控（3 分钟间隔）、1 个状态页、1 名响应人、邮件和 Slack 通知；**运行节点可以把额度换成更多监控和更短间隔** | 免费 |
| **团队 Team** | 不限监控（按额度或用量）、电话和短信、多人排班、升级策略、外部告警源、去掉 Powered by | 按响应人每月收费，明显低于 PagerDuty |
| **商业 Business** | 私有节点、带凭证的检查、SSO、月度 SLA 报告、私有状态页、数据驻留 | 按响应人收费 + 私有节点费用 |
| **企业 Enterprise** | 私有节点池、自建协调者（以后）、定制合同和 SLA | 年度合同 |

- 付费用户的检查优先使用基线节点托底，有 SLA 保证。
- 电话和短信按量计费，或者在套餐里包含一定数量。
- 考虑：给开源项目和非营利组织免费的团队档。

## 风险

| 风险 | 应对 |
|---|---|
| **冷启动**：一开始没有足够的社区节点 | 基线节点覆盖全部基本需求；社区节点是“锦上添花”，从邀请制开始 |
| **恶意节点**：造假或者被攻破 | 共识门槛、信誉、金丝雀检查、同一运营者只算一个来源 |
| **网络被滥用**：成为 DDoS 或扫描工具 | 目标所有权验证、全网频率上限、节点不能选目标 |
| **节点运营者的法律风险** | 只请求经过验证的目标、统一 User-Agent、条款写清楚 |
| **电话和短信的成本和欺诈** | 号码验证、频率上限、免费档限额 |
| **被误认为是加密货币项目** | 不发币、额度不能转让和提现、营销中不用 Web3 词汇 |
| **竞争激烈**：Better Stack、UptimeRobot、Uptime Kuma、PagerDuty 等 | 差异化在“多方确认 + 可验证 + 社区网络”，以及只做 uptime 和值班 |
| **Opsgenie 迁移窗口的时间点不确定** | 上线前核实 Atlassian 的公告，据此安排营销节奏 |
| **监控自己的监控**：Corro 自己挂了怎么办 | 协调者多区域部署；状态页静态托管；Corro 自己的状态页由独立的第三方监控 |
