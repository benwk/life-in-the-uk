# 设计简报 Design Brief

> 这份简报是给 **Claude Design**（或任何设计师）用的。品牌性格和语气见 [品牌手册](../brand/brand-book.md)；产品细节见 `docs/product/`；各屏幕的设计提示词见 [screen-prompts.md](screen-prompts.md)，可以直接复制使用。

## 1. 我们在做什么

**Corro** 是一个 uptime 监控、值班告警和状态页产品。它的特别之处是：

1. **社区节点网络**：任何人都能运行节点加入网络，服务被全球多个独立视角同时看着。
2. **多方确认**：一个节点看到故障只算“疑似”；多个国家、多个运营者的节点一致，才算“已确认”，才会叫醒人。
3. **可以验证**：每个结论都有签名和凭证（Receipt），连 Corro 自己也改不了。
4. **冷静**：用户是值班的人，可能凌晨三点刚被叫醒。

## 2. 视觉关键词

| 是 | 不是 |
|---|---|
| 冷静 Calm | 警报灯、满屏红色 |
| 精确 Precise | 装饰性的花哨图表 |
| 集体 Collective | 孤立的单点、英雄主义 |
| 可信 Trustworthy | 加密货币风：霓虹、发光、链条、硬币 |
| 有生命 Alive | 冷冰冰的静态后台 |
| 工艺感 Crafted | 千篇一律的 SaaS 模板 |

**一句话的感觉**：*像一座安静的控制塔，周围有一圈朋友帮你看着；出事时，它用最少的话告诉你最确定的事实。*

参考气质（只参考气质，不抄样式）：Linear 的克制和精确、Stripe 文档的清晰、瑞士平面设计的网格和留白、热敏打印小票的质感（只用在 Receipt 上）。

## 3. 核心视觉隐喻

| 元素 | 灵感来源 | 用在哪里 |
|---|---|---|
| ⭕ **点环 The Circle** | 一圈节点围着一个目标；西语 *corro* = 围成一圈的人 | Logo、加载、确认动画、监控详情的节点圈、空状态 |
| ✓ **见证标记 Witness marks** | 每个节点给出的勾或叉 | 确认过程、事故时间线、通知 |
| 🧾 **小票 Receipt** | 热敏打印小票：等宽字体、虚线分隔、锯齿边、微微泛黄的纸 | Receipt、SLA 报告、分享卡片。**整个产品里唯一的拟物元素** |
| 🗺️ **点阵地图 Dot-matrix map** | 由均匀小圆点组成的世界地图，节点所在的点亮起 | 见证地图、网络浏览器、营销站 |
| ▮ **可用率条 Uptime bars** | 一天一格的竖条 | 状态页、监控详情 |
| 🌙 **夜班 Night shift** | 凌晨的控制室：深色、低亮度、只有关键信息发光 | 深色模式、值班 App 的告警页 |

**避免**：心电图式的心跳线、地球仪加飞线、雷达扫描。这些在监控产品里已经被用烂了。

## 4. 配色方向（建议，欢迎推翻）

基调：**中性的纸白和墨黑 + 一个品牌色**。状态色有严格的含义，只用于表达状态。

### 中性色和品牌色

| Token | 浅色模式 | 深色模式 | 用途 |
|---|---|---|---|
| `bg` | `#F7F7F5` | `#0B0E13` | 页面背景 |
| `surface` | `#FFFFFF` | `#141922` | 卡片、面板 |
| `line` | `#E3E5E8` | `#232A35` | 分隔线、边框 |
| `ink` | `#0F1419` | `#E8EBEF` | 主要文字 |
| `ink-muted` | `#5B6470` | `#8C95A1` | 次要文字 |
| `circle` | `#2E4BE0` | `#6D84FF` | 品牌色：主按钮、链接、选中状态、Logo 强调 |
| `receipt` | `#FBF8F1` | `#1B1A17` | Receipt 的纸张颜色 |

### 状态色（含义固定，任何地方都不能挪作他用）

每个状态都有一个**填充色**（用于图标、圆点、条）和一个**文字色**（用于浅色背景上的文字，保证 WCAG AA）。

| 状态 | 形状 | 填充色 | 文字色（浅色背景） |
|---|---|---|---|
| Up | ● | `#12A150` | `#0B7A3B` |
| Suspect | ◐ | `#E0A100` | `#8A6100` |
| Down | ▲ | `#E5484D` | `#C62A2F` |
| Degraded | ◆ | `#F2711C` | `#B4520E` |
| Maintenance | ◇ | `#8E5CD9` | `#6B3FB5` |
| Paused / Unknown | ‖ / ○ | `#8A919C` | `#5B6470` |

规则：

- **红色只用于 Down。**错误提示、删除按钮等用中性色或品牌色加图标，不用红色。
- **状态永远是“形状 + 颜色 + 文字”三件套**，色盲用户（尤其是红绿色盲）也能分辨。
- 一切正常的页面上，几乎只看得到中性色和少量绿色圆点。颜色越少，出事时越醒目。
- 图表中的分类颜色（比如不同地区的响应时间曲线）要从一组**和状态色不冲突**的颜色里选，例如品牌色的不同明度加青、靛、灰。

### 三种“皮肤”

| 皮肤 | 用在哪 | 特点 |
|---|---|---|
| **日间 Day** | 控制台、营销站默认 | 纸白背景，安静、通透 |
| **夜班 Night** | 深色模式；值班 App 夜间默认 | 深墨背景，低亮度，只有状态色和关键数字发光 |
| **客户品牌 Customer** | 状态页 | 客户的 Logo 和主色替换 `circle`；中性色和状态色不变 |

## 5. 字体

| 用途 | 字体建议 |
|---|---|
| 界面和正文 | **Inter**（或 Geist），使用等宽数字（tabular figures） |
| 大标题和营销 | Inter Display，或者一款有性格的几何无衬线（如 Space Grotesk），只用在营销站 |
| 等宽 | **JetBrains Mono**（或 Geist Mono）：哈希、ID、时间戳、终端、Receipt |
| 中文 | Noto Sans SC / TC，或系统字体（苹方） |
| 其他文字系统 | Noto 家族（状态页要支持多语言和从右往左书写的语言） |

规则：

- **数字很重要**：可用率、响应时间、持续时间用等宽数字，排成一列时要对齐。
- 时间戳统一格式，例如 `09:41:12 UTC`；界面上同时提供本地时间。
- 大号数字（比如 `99.98%`）可以作为页面的视觉焦点。

## 6. 图形和插画

- **不用人物插画**。Corro 的“角色”就是那一圈点。
- 图标：线性、1.5px 描边、圆角端点，和点环的几何感一致。
- 空状态：用点环的变体来表达，比如一个只有一个点的圈，配文“还没有监控”；节点越多，圈越完整。
- 点阵地图：均匀的小圆点；只亮起有节点或者有见证的城市；**不显示精确位置**。
- Receipt 的质感：轻微的纸纹、上下锯齿边、虚线分隔、等宽字体。只在 Receipt、SLA 报告和分享卡片上使用。

## 7. 数据可视化

| 组件 | 说明 |
|---|---|
| **节点圈 Witness ring** | 产品的标志性组件：目标在中心，节点在外圈，每个节点显示自己的结果（形状 + 颜色）。要能从 16px（列表里的小图标）缩放到整屏（事故详情）。小尺寸时简化成“4/5 ✓”这样的分段圆环 |
| **可用率条 Uptime bars** | 90 天，一天一格；格子高度一致，只用颜色和形状区分；没有数据的日子用空格 |
| **响应时间图** | 按地区分组的折线；默认显示中位数和 p95；故障区间用浅色背景标出 |
| **事故时间线** | 竖向时间线：左边是时间（等宽），中间是状态符号，右边是事件描述；被否决的疑似用浅色显示 |
| **见证地图** | 点阵地图 + 节点结果；区域性故障时，受影响的区域整体着色 |

## 8. 动效

| 场景 | 动效 |
|---|---|
| **确认动画**（标志性） | 目标在中心，节点在外圈依次亮起并给出勾；勾全部到齐后，细线从各节点汇聚到中心，中心出现“Corroborated”状态。5–8 秒，用在首次使用和营销站；产品内部用 1 秒的简化版 |
| 疑似 | 状态点变成半圆，缓慢地呼吸一次（不循环闪烁） |
| 宕机 | **不闪烁**。状态平稳切换成红色三角，同时出现事故横幅 |
| 恢复 | 圆环重新闭合，回到绿色实心圆 |
| 加载 | Logo 的点依次亮起 |
| 节点挣到额度 | 节点页上一个小小的“+1”从见证标记飞向余额 |

所有动效都要支持系统的“减少动态效果”设置，开启后改为直接切换。**任何状态都不使用闪烁效果**，避免引起不适，也避免制造恐慌。

## 9. 声音（值班 App）

| 场景 | 声音方向 |
|---|---|
| 告警 | 一个清晰的两音动机，暗合 “cor-ro” 两个音节；不刺耳，但在嘈杂环境和睡梦中都能听到。重复时逐渐变响 |
| 确认（Ack） | 一个短促的确认音 |
| 恢复 | 两个下行的柔和音，传达“解除了” |
| 疑似 | 默认不发声音 |

不要用警笛、蜂鸣器这类会让人心跳加速的声音。

## 10. 关键设计挑战（请重点探索）

1. **节点圈组件**：怎样一眼看出“多少节点、来自哪里、结论是什么、有多确定”？从列表里的小图标到事故详情的整屏，怎样保持一致？
2. **凌晨三点的告警页**：刚醒的人 10 秒内要知道发生了什么，并且能单手完成确认。
3. **平静的控制台**：一个团队可能有几百个监控，一切正常时页面要安静，出问题时异常要自己“浮出来”。
4. **状态页的 5 秒**：在客户品牌定制和全球一致的状态语言之间找平衡；手机上第一屏就要有答案。
5. **让密码学证明变得亲切**：Receipt 和验证流程不能吓人，非技术用户也要能看懂“✓ 已验证”意味着什么。
6. **网络的生命感**：营销站和网络浏览器要让人感觉这个网络是活的、属于大家的，同时不暴露节点的精确位置。
7. **和加密货币划清界限**：涉及节点、额度、透明日志的界面，要传达“可信”和“开放”，但绝不能让人联想到币圈。
